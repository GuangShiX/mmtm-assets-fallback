# MementoMori Lightweight Data Fallback

Small GitHub-hosted set of MementoMori icons and character skills used by
[`mementomori-helper`](https://github.com/GuangShiX/mementomori-helper-GXmaster) and generated by
[`mmtm-apk-tracker`](https://github.com/GuangShiX/mmtm-apk-tracker).

This repository is the primary low-traffic data source. It does not contain
APKs, complete character artwork, raw Unity objects, or complete Master databases.

## Contents

```text
assets/
  characters/   # Complete published player avatars and small character portraits
  enemies/      # Enemy portraits
  equipment/    # Equipment icons
  spheres/      # Rune/sphere icons
  items/        # Common item icons
  ui/           # Shared UI plus locked Prefab Sprite dependencies
manifest.json   # Stable paths, sizes, and SHA-256 hashes
latest.json     # Current stable manifest URL
skills/
  characters/   # One validated JSON document per released character
  index.json    # All released characters, ordered by release time
  manifest.json # Stable paths, sizes, hashes, and source MasterBook hashes
  latest.json   # Latest released character(s), selected by StartTimeFixJST
cards/
  characters/   # Accepted 3840x2500 landscape skill cards using official art
preview/
  skills/       # Explicit unreleased previews, separate from released indexes
  cards/        # Unreleased landscape cards and their own manifest
  index.json    # Preview IDs, status, and missing official-data notices
```

Consumers should request
[`manifest.json`](https://raw.githubusercontent.com/GuangShiX/mmtm-assets-fallback/main/manifest.json)
and cache each selected file locally after verifying its SHA-256. Asset URLs
are built as `{base_url}/{path}`.

Public image URLs use stable `main/assets/...` paths without a game version.
The game version remains metadata, and `v<game-version>` tags are retained only
for rollback. Consumers detect rare same-path changes through the manifest hash.

Character skill consumers should start from
[`skills/latest.json`](https://raw.githubusercontent.com/GuangShiX/mmtm-assets-fallback/main/skills/latest.json)
or
[`skills/index.json`](https://raw.githubusercontent.com/GuangShiX/mmtm-assets-fallback/main/skills/index.json).
Each character document contains active/passive skill levels, exclusive-weapon
passive attributes and skill effects, Arcana membership and level effects,
localization keys, available official
localized text, and the Japanese source `Memo` retained from the skill MasterBook.
`localization_complete: false` means the character/skill
record has arrived before the requested official language table was updated;
missing text is never guessed.

## 角色海报与未实装预览

后续海报统一使用已验收的 `split` 横版模板（3840×2500）：左侧展示官方登场横幅、属性与职业图标、ID、名称和完整立绘；右侧上排并列两个主动技能，下排并列两个被动技能；底部展示专属武器和秘仪。专武栏标题右侧标注来自官方 `CharacterMB` 的**初始速度**，不叠加养成或装备效果。技能名称、专武和秘仪名称使用清晰的加粗字重，水印放在角落。

正式海报文件为 `cards/characters/character-<六位ID>-split-zh-CN.png`，由 `cards/manifest.json` 记录数据哈希、模板版本、图片尺寸和校验值。只在正式角色索引中选择当前已实装角色。

2100 年等占位日期记录单独写入 `preview/skills/`，海报写入 `preview/cards/characters/`；`preview/index.json` 标注“未实装预览”。它们不会进入 `skills/latest.json` 或正式角色索引。缺失的官方登场横幅、专武或秘仪会明确标注暂未公开，不补写官方美术文字，不猜测数据。

仓库维护者可在 tracker 中使用 `character_release.py` 固定同一份官方版本快照，复用校验过的主表和资源缓存，分步恢复下载、导出和海报生成；正式与预览海报分别校验。缓存命中且数据、模板和图片哈希均未变化时跳过重绘。用法见 tracker 的[角色发布流程](https://github.com/GuangShiX/mmtm-apk-tracker/blob/master/docs/character-release-workflow.md)。CI 保留主表、图片和海报各自的校验门禁，通过的正式数据可独立发布。

## Updating

The scheduled workflow checks the official application version, BOI
Addressables asset version, and Master version at three daily baseline times.
A lightweight 15-minute probe also reads the anonymous title notice feed and
the structured `getDataUri` maintenance schedule. On maintenance days, the full
updater runs from 15 minutes after the official start through 15 minutes after
the official end; unrelated regional or feature-only maintenance is ignored.
Same-version hot updates download only critical image bundles listed by the
official catalog. A new application
version downloads the official APK once and scans its bundles without creating
a full multi-million-file extraction. The Master updater validates downloaded
MessagePack books against `master-catalog`, then selects released characters by
`StartTimeFixJST` rather than assuming IDs are monotonic. Before requesting card
assets, CI compares the latest skill JSON, landscape-template version, output size,
and PNG hash with `cards/manifest.json`; current cards make no official resource
request. Verified image and skill JSON updates are committed independently of
derived card rendering, so a temporarily missing card asset does not delay
official skill text publication. Cards remain excluded until their own
verification passes. Changes are committed automatically; `v<game-version>`
tags are retained only for rollback.

Official art policy lives in the tracker's `config/official_asset_requests.json`
and generated `config/player_avatar_inventory.json`; files are never copied into
this repository by hand. The repository keeps every published compact player
avatar that can be traced to `CharacterMB` or `SpecialIconItemMB`, plus canonical
small-icon families for characters, enemies, equipment, items, and spheres.
Master rows reserved without an official image remain audit records and are not
published as fake or missing files. Larger UI and scene art is still added only
for an identified consumer.

The image job treats the combined request and avatar-inventory SHA-256 as an
update key, rebuilds the official package subset when it changes, discovers
matching official sprites, merges Addressables targets, and then runs
`asset_requests.py verify-repository`. A data commit is blocked unless every
required asset has a canonical path, matching size/hash, valid PNG data, source
evidence, and a complete current request fingerprint. Published differential
avatars must also map back to the current `SpecialIconItemMB` inventory.

# MementoMori Lightweight Data Fallback

Small GitHub-hosted set of MementoMori icons and character skills used by
[`mementomori-helper`](https://github.com/GuangShiX/mementomori-helper-GXmaster) and generated by
[`mmtm-apk-tracker`](https://github.com/GuangShiX/mmtm-apk-tracker).

This repository is the primary low-traffic data source. It does not contain
APKs, complete character artwork, raw Unity objects, or complete Master databases.

## Contents

```text
assets/
  characters/   # Small character portraits
  enemies/      # Enemy portraits
  equipment/    # Equipment icons
  spheres/      # Rune/sphere icons
  items/        # Common item icons
  ui/           # Shared UI plus locked Prefab Sprite dependencies
manifest.json   # Stable paths, sizes, and SHA-256 hashes
latest.json     # Current stable manifest URL
skills/
  characters/   # One validated JSON document per released character
  index.json    # All released characters, ordered by release time
  manifest.json # Stable paths, sizes, hashes, and source MasterBook hashes
  latest.json   # Latest released character(s), selected by StartTimeFixJST
cards/
  characters/   # Uniform skill introduction posters using official character art
```

Consumers should request
[`manifest.json`](https://raw.githubusercontent.com/GuangShiX/mmtm-assets-fallback/main/manifest.json)
and cache each selected file locally after verifying its SHA-256. Asset URLs
are built as `{base_url}/{path}`.

Public image URLs use stable `main/assets/...` paths without a game version.
The game version remains metadata, and `v<game-version>` tags are retained only
for rollback. Consumers detect rare same-path changes through the manifest hash.

Character skill consumers should start from
[`skills/latest.json`](https://raw.githubusercontent.com/GuangShiX/mmtm-assets-fallback/main/skills/latest.json)
or
[`skills/index.json`](https://raw.githubusercontent.com/GuangShiX/mmtm-assets-fallback/main/skills/index.json).
Each character document contains active/passive skill levels, exclusive-weapon
passive attributes and skill effects, Arcana membership and level effects,
localization keys, available official
localized text, and the Japanese source `Memo` retained from the skill MasterBook.
`localization_complete: false` means the character/skill
record has arrived before the requested official language table was updated;
missing text is never guessed.

The scheduled renderer uses those JSON documents together with the official
character avatar, exclusive-weapon icon, and four official skill icons. For each
newly released character it publishes one deterministic 2160x3840 text-first
portrait card. The card uses an unobstructed character avatar one size tier above
the matching skill/weapon icons, places the four large-type skill summaries first,
merges all level/weapon upgrades into final effects, and moves the three LR weapon
passives, `LR专效果`, the Arcana LR effect, and required-character portraits to the
bottom. Stable filenames are
`cards/characters/character-<six-digit-id>-compact-zh-CN.png`.

## Updating

The scheduled workflow checks the official application version, BOI
Addressables asset version, and Master version every six hours. Same-version hot updates download
only critical image bundles listed by the official catalog. A new application
version downloads the official APK once and scans its bundles without creating
a full multi-million-file extraction. The Master updater validates downloaded
MessagePack books against `master-catalog`, then selects released characters by
`StartTimeFixJST` rather than assuming IDs are monotonic. Before requesting card
assets, CI compares the latest skill JSON, portrait-template version, output size,
and PNG hash with `cards/manifest.json`; current cards make no official resource
request. New or stale cards are rendered and verified before any data commit.
Changes are committed automatically; `v<game-version>` tags are retained only for
rollback.

Official art is added on demand through the tracker's
`config/official_asset_requests.json`, not by copying files into this repository.
The image job treats that request file's SHA-256 as an update key, rebuilds the
official package subset when the request set changes, merges exact Addressables
targets, and then runs `asset_requests.py verify-repository`. A data commit is
blocked unless every requested asset has a canonical path, matching size/hash,
valid PNG data, source evidence, and a complete current request fingerprint.
